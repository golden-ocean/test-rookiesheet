什么是所有权

基础 阅读约 8 分钟·含 1 道小测验

所有权是 Rust 管理内存的方式。它不靠垃圾回收，也不要求你手动释放，而是在编译时检查几条规则。违反规则的程序不会通过编译。

本节目标：读完后，你能说出所有权的三条规则，并判断一段代码里的值是否已被移动。

所有权规则

  • 每个值都有一个所有者。
  • 同一时间，一个值只能有一个所有者。
  • 所有者离开作用域时，这个值会被丢弃。

第二条最容易被忽略：把值赋给另一个变量，所有权会转交过去。

移动

下面的代码把 s1 赋给 s2 后，再使用 s1，编译器会报错。

let s1 = String::from("hello");
let s2 = s1;
println!("{s1}"); // 错误：s1 的值已移动

赋值之后，s1 不再有效。这样做避免了两个变量在离开作用域时重复释放同一块内存。

克隆

如果确实需要两份数据，用 clone 显式复制。代价是多一次堆内存的拷贝。

let s1 = String::from("hello");
let s2 = s1.clone();
println!("{s1} {s2}"); // 正常运行

栈与堆

要理解为什么 String 会被移动而整数不会，先看这两种内存区域的区别。

栈堆
存放内容大小固定的值，如 i32大小可变的值，如 String
分配速度快，只需移动栈顶指针较慢，要先找到足够的空位
访问方式直接访问通过指针间接访问
与所有权的关系复制开销小，直接拷贝所有权规则主要管理这部分数据

常见问题

整数赋值后，原变量为什么还能用？

整数这类类型实现了 Copy，赋值时按位复制，原变量依然有效。只有管理堆数据的类型才会发生移动。

把值传给函数也会移动吗？

会。传参和赋值规则一致：String 传进函数后，调用方就不能再用它了。下一节的“借用”专门解决这个问题。

移动会让程序变慢吗？

不会。移动只复制栈上的指针、长度和容量三个字段，不会拷贝堆里的数据。

本节小结

  • ✓每个值只有一个所有者。
  • ✓赋值和传参会移动所有权，原变量随即失效。
  • ✓需要两份堆数据时，显式调用 clone。
  • ✓Copy 类型（如整数）赋值后仍可继续使用。
